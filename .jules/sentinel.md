## 2024-10-03 - [CRITICAL] Node.js VM Sandbox Escape via Prototype Chain Traversal
**Vulnerability:** The `executeSanitizedUserCode` function in `backend/src/utils/codeRunner.js` passed standard host objects (`process.env`) directly into the VM sandbox context and allowed code generation from strings. This permitted a VM sandbox escape through prototype chain traversal (e.g. `this.constructor.constructor("return process")()`), leading to remote code execution (RCE) on the host environment.
**Learning:** Using `Object.create(null)` is critical for *all* nested context objects when passing them into a Node.js VM. Simply isolating the root context isn't sufficient if standard host objects are injected, as their prototype chains traverse back to the host execution context. Furthermore, explicitly disabling code generation from strings in `vm.createContext({ codeGeneration: { strings: false, wasm: false } })` and using `vm.runInContext` (instead of `vm.runInNewContext`) closes code injection attack vectors.
**Prevention:** 1) Always use `vm.createContext({ codeGeneration: { strings: false, wasm: false } })`. 2) Ensure all objects (and sub-objects) injected into the context are created using `Object.create(null)` to eliminate prototype traversal. 3) Avoid injecting host-created functions (like `process.exit`) which can leak the `Function.prototype`.
