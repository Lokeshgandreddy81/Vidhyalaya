## 2025-02-20 - SSRF Vulnerability in Custom AI Endpoints
**Vulnerability:** A Server-Side Request Forgery (SSRF) vulnerability existed in `backend/src/utils/aiClientRouter.js` where user-provided `customEndpoint` URLs for OpenAI, Groq, OpenRouter, and Anthropic REST/Stream integrations were directly passed to `fetch()` without IP or protocol validation.
**Learning:** Permitting custom API endpoints for third-party service integration introduces a vector for interacting with internal network resources or cloud metadata endpoints. While basic URL parsing and IP checking are common mitigations, Node.js HTTP clients (like `fetch`) perform independent DNS lookups. A pre-flight IP check using `dns.lookup` is a good first step, but it is technically susceptible to DNS Rebinding (TOCTOU attacks) unless the connection is explicitly pinned to the validated IP.
**Prevention:** Always validate and restrict custom endpoint URLs to the `https:` protocol. Enforce strict blacklists against loopback, RFC 1918 internal, and RFC 4193 ULA IPv4/IPv6 addresses, accounting for IPv4-mapped IPv6 representations (e.g., `::ffff:127.0.0.1`). For bulletproof prevention against DNS Rebinding, configure the underlying HTTP client (e.g., using `undici` Agent with a custom DNS lookup function) to pin the network request to the pre-validated IP address, rather than relying solely on a pre-flight validation check.
