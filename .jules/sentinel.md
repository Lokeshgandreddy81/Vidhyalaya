## 2025-02-14 - Fix VM Sandbox Escape in executeSanitizedUserCode
**Vulnerability:** Sandbox escape vulnerability via prototype chain pollution in `executeSanitizedUserCode` allowing arbitrary code execution (RCE). The VM isolation approach was using an improperly constructed context object containing standard node.js objects like `process.env.constructor` that leaked references to the main context.
**Learning:** Initializing the VM context sandbox object with `{ ... }` keeps its original prototype chain, which attackers can traverse (e.g. `this.constructor.constructor('return process')()`). Relying on host-created functions inside the sandbox context also retains `Function.prototype` links. Furthermore, `runInNewContext` with default `codeGeneration` settings allows executing dynamic strings, which is inherently dangerous.
**Prevention:** Always use `Object.create(null)` to instantiate the root sandbox object and all nested child properties to eliminate prototype traversals. Enforce explicit `codeGeneration` constraints by initializing context securely with `vm.createContext({ ... }, { codeGeneration: { strings: false, wasm: false } })` and using `vm.runInContext` instead of `vm.runInNewContext`. Avoid injecting host-originated functions entirely.
