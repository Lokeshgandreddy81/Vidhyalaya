## 2025-06-06 - Enforce Default User Identity in Development Auth Bypass Endpoint
**Vulnerability:** The `/token` endpoint in `backend/src/routes/auth.js` allowed generation of a valid JWT token for any arbitrary `userId`. Although protected by `if (process.env.NODE_ENV === 'production')`, in dev/testing environments, this allowed complete authentication bypass.
**Learning:** Development utility endpoints (backdoors) that exist for ease of bootstrapping can be exploited if accidentally exposed or if environment configuration falls back to default. In this case, the frontend legitimately depended on this endpoint for an unauthenticated `"default-user"` experience, highlighting the danger of coupling dev endpoints with application features.
**Prevention:** Strictly restrict dev fallback endpoints to hardcoded expected identities (e.g., `'default-user'`) instead of accepting arbitrary payload data. Avoid using dev bypass routes to handle production/unauthenticated scenarios.
