## 2024-09-11 - VM Sandbox Escape via process.env.constructor
**Vulnerability:** The `executeSanitizedUserCode` function in `backend/src/utils/codeRunner.js` used `runInNewContext` with a plain JavaScript object as the sandbox context. By injecting host objects (like `process.exit = () => {}` or standard nested objects), the prototype chain was exposed. Malicious code could traverse the prototype chain (e.g., `process.env.constructor.constructor('return process')()`) to escape the VM sandbox and gain full execution access in the host context.
**Learning:** Initializing a Node.js VM sandbox with standard objects is insufficient for isolation, as their prototypes inherently link back to the host environment, allowing for trivial escape using constructor access.
**Prevention:** To secure the VM: use `vm.createContext` with `codeGeneration: { strings: false, wasm: false }`, execute via `vm.runInContext`, ensure ALL nested objects are created recursively via `Object.create(null)` to eliminate prototypes, and completely avoid injecting host-created functions (which retain `Function.prototype`).
