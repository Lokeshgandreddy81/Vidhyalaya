
## 2026-10-26 - Prevent VM Sandbox Escape in Code Runner
**Vulnerability:** A Remote Code Execution (RCE) vulnerability existed in `backend/src/utils/codeRunner.js`. The Node.js `runInNewContext` was used with an insecure context object containing a function from the main context (`exit`), and without disabling code generation from strings. An attacker could bypass the VM by using prototype chain traversal on the injected function (e.g., `process.exit.constructor('return process')()`) to gain full access to the main Node.js process.
**Learning:** `vm.runInNewContext` is not inherently secure, especially when host objects or functions are injected. Any function from the main context carries its `constructor` property, allowing access to the main `Function` constructor which evaluates strings in the host environment. Furthermore, standard object literals inherit from `Object.prototype`, which can also be leveraged for escapes.
**Prevention:** Always use `vm.createContext` combined with `runInContext`. Disable `eval` and `new Function` execution by setting `{ codeGeneration: { strings: false, wasm: false } }`. When injecting context, avoid passing functions created in the host context entirely. If objects must be passed, ensure they and all nested properties are created using `Object.create(null)` to eliminate prototype inheritance.
