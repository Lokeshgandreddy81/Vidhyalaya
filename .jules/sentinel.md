## 2024-10-25 - [VM Sandbox Escape Vulnerability Fix]
**Vulnerability:** The Node `vm` sandbox was insecurely initialized by using an object literal (`{}`) as the sandbox context, and passing host-instantiated functions like `process.exit = () => {}` into it. This permitted sandbox escape attacks where an adversary could access `Object.prototype` or `Function.prototype` (e.g. `process.env.constructor.constructor('return process')()`) to break out of the sandbox and execute arbitrary code on the server.
**Learning:** Using `Object.create(null)` is required to prevent prototype chain traversal for all sandbox context objects, and passing functions created on the host thread into the sandbox retains `Function.prototype` references that break isolation. `codeGeneration: { strings: false, wasm: false }` adds another layer of defense against string-to-code eval attacks.
**Prevention:** Always initialize all objects explicitly with `Object.create(null)` when creating contexts, enforce safe options on `vm.createContext`, and strictly prevent host-instantiated functions from entering the sandboxed context.
