
## 2024-09-23 - Fix VM Sandbox Escape via Prototype Chain Traversal
**Vulnerability:** The `executeSanitizedUserCode` function in `backend/src/utils/codeRunner.js` used `runInNewContext` with a standard object literal to define the sandbox context. This allowed user-provided code to escape the sandbox by accessing the host environment's prototype chain via `this.constructor.constructor('return process')()`, gaining full access to the application's environment variables (e.g., API keys).
**Learning:** Initializing a VM sandbox context with `{}` or even injecting standard host functions (like `process.exit = () => {}`) inherently exposes the `Object.prototype` and `Function.prototype` of the main Node.js process to the sandbox environment. This makes `runInNewContext` trivial to escape.
**Prevention:** Always use `vm.createContext` initialized with a fully isolated environment created via `Object.create(null)`. Ensure all nested objects within the context mask are also instantiated with `Object.create(null)` to completely destroy any prototype linkages to the host. Additionally, apply `codeGeneration: { strings: false, wasm: false }` to prevent dynamic execution payloads inside the sandbox.
