## 2025-02-14 - Fix VM sandbox escape vulnerability
**Vulnerability:** The Node.js `vm` module sandbox implementation for executing untrusted user code in `backend/src/utils/codeRunner.js` was initialized using standard object literals (`{}`) and injected a host function (`process.exit: () => {...}`). This allowed malicious scripts to access the host environment's execution context by traversing the prototype chain (e.g., `process.env.constructor.constructor('return process')().env`), leading to a sandbox escape that could potentially view sensitive environment variables or execute system commands.
**Learning:** Initializing VM contexts in Node.js using standard objects and injecting host functions inherently ties the sandbox's prototype chain to the main host context. `vm` contexts share the `Object` prototype by default unless explicitly detached.
**Prevention:** Always initialize `vm` sandbox context objects (and all recursively nested objects) using `Object.create(null)` to ensure they have no prototype. Never inject host-created functions (like `exit` or callbacks) into the sandbox, as their `.constructor` will retain a reference to the host's `Function.prototype`. Furthermore, enforce strict context boundaries by configuring context creation with `{ codeGeneration: { strings: false, wasm: false } }` to block arbitrary `eval` and `new Function` execution, which provides defense-in-depth against code execution payloads.
