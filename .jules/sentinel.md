## 2024-03-20 - SSRF Vulnerability via Custom Endpoint in aiClientRouter.js
**Vulnerability:** The `aiClientRouter.js` allows arbitrary `x-byok-endpoint` headers for OpenAI, Groq, OpenRouter, and Anthropic providers. These endpoints are fetched directly using Node's `fetch` without validating the domain or the resolved IPs, leading to a Server-Side Request Forgery (SSRF) vulnerability. This could allow an attacker to send requests to internal services (e.g., AWS Metadata service at 169.254.169.254, internal databases on loopback or private networks, or perform port scanning on the internal network).
**Learning:** `fetch` in Node.js does not prevent internal IP connections by default. When allowing custom API endpoints for third-party AI integrations, trusting user-supplied URLs blindly creates SSRF vectors. Validation needs to parse the URL, verify the protocol is `https:`, and perform DNS resolution to check if the destination IP is within a restricted or internal range. DNS rebinding must also be considered.
**Prevention:** Always validate and normalize URLs. Restrict the protocol to `https:`. Perform DNS lookup with `{ all: true }` and reject if any resolved IP address belongs to internal ranges (loopback, private IPv4/IPv6, link-local, etc.). The final `fetch` must either reuse the validated IP directly or let standard fetch do it, but to prevent TOCTOU with standard fetch, network isolation or an HTTP agent with a custom lookup function is preferred. If `fetch` is used natively without agent customization, checking the hostname's DNS records just before fetch is an acceptable first layer, though less robust than an overriding agent. In this codebase's context, as per memory, we must use `dns.lookup` wrapped in `try/catch`, ensuring `https:` and rejecting internal/reserved IPs, and do *not* replace the hostname with the IP in the final `fetch` URL to preserve TLS/SNI.
