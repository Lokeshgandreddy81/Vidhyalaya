## 2024-05-20 - [SSRF via Unvalidated Custom AI Endpoints]
**Vulnerability:** A Server-Side Request Forgery (SSRF) vulnerability existed where users could provide custom AI endpoints (`x-byok-endpoint` headers). The backend parsed this and directly issued HTTP requests via `fetch` to whatever endpoint the user specified without checking if the endpoint resolved to internal infrastructure, local services, or cloud metadata endpoints.
**Learning:** Even heavily customized external services (like LLM APIs) can be weaponized into network scanning tools or used to access internal microservices/metadata if the user can arbitrarily direct outgoing HTTP traffic. Enforcing `https` prevents hitting most local services, and resolving and verifying DNS addresses prior to issuing requests is crucial for BYOK (Bring Your Own Key/Endpoint) features.
**Prevention:** Always parse, enforce HTTPS, and resolve DNS using `dns.lookup({all:true})` for any user-controlled outgoing URL. Validate all resolved IPs against loopback, unroutable, and internal RFC 1918 ranges, explicitly catching edge cases like IPv4-mapped IPv6 loopbacks before initiating the request.
