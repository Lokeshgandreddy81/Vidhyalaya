## 2026-07-15 - Prevent SSRF in AI Client Router via x-byok-endpoint Validation
**Vulnerability:** The application allowed users to specify a custom LLM proxy endpoint via the `x-byok-endpoint` HTTP header in `aiClientRouter.js`. This user-supplied URL was directly passed to `fetch()` without any validation, enabling Server-Side Request Forgery (SSRF). An attacker could exploit this to port-scan internal networks, access internal services (e.g., `localhost:8080`), or retrieve sensitive cloud instance metadata (e.g., AWS IMDS via `169.254.169.254`).
**Learning:** External or custom proxy endpoints supplied by users must be explicitly vetted before being accessed by the backend HTTP client. It is not enough to rely on network firewalls if the backend itself acts as a confused deputy.
**Prevention:** Implement a strict pre-flight URL validation function (`validateEndpointUrl`) that ensures the protocol is `https:`, normalizes IPv6 formatting, and actively blocks resolution to any internal, reserved, loopback, or local IP address ranges using both regex and active DNS lookup (`dns.promises.lookup` with `all: true`). Apply this validation before any `fetch` calls utilizing the custom endpoint.
