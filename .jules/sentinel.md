## 2024-05-15 - SSRF via Custom LLM Endpoint Injection
**Vulnerability:** The AI client router (`aiClientRouter.js`) accepted user-provided custom LLM endpoints via the `x-byok-endpoint` header and passed them directly to `fetch` calls without validation. This allowed an attacker to supply internal loopback IPs or metadata service IPs (like `169.254.169.254`) and achieve Server-Side Request Forgery (SSRF) to scan internal networks or extract sensitive data.
**Learning:** Even when building pass-through proxy endpoints for "Bring Your Own Key" (BYOK) architectures, we must validate URLs explicitly before any backend HTTP fetches occur, because generic HTTP clients (`fetch`) will blindly resolve and request internal subnets if permitted.
**Prevention:** Created a centralized `validateEndpointUrl` utility enforcing HTTPS and strictly validating the resolved IP address against known internal subnets (`127.x`, `169.254.x`, `10.x`, etc.) directly from the URL string and post-DNS resolution to catch DNS rebinding and customized local hostnames.
