## 2024-05-24 - [Fix SSRF in custom endpoint routing]
**Vulnerability:** The application allowed users to specify a custom AI provider endpoint via the `x-byok-endpoint` header. This endpoint was passed directly to `fetch` calls without validation, leading to a Server-Side Request Forgery (SSRF) vulnerability. An attacker could probe internal IPs (e.g., 127.0.0.1, 169.254.169.254) or metadata endpoints.
**Learning:** External user input used to construct network requests must be strictly validated. Relying solely on regex for URLs is insufficient for SSRF protection because attackers can obfuscate IPs or use custom domains pointing to internal IPs.
**Prevention:** Implement an `isSafeEndpoint` validation function that parses the URL, enforces HTTPS, and resolves the hostname using `dns.lookup` to verify the resulting IPs do not fall into private, loopback, or link-local address spaces. Use `dns.promises.lookup` with `{ all: true }` to check all IPs and prevent DNS rebinding attacks.
