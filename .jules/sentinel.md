## 2024-05-24 - [Critical] Prevent VM Sandbox Escape in execution environment
**Vulnerability:** Node.js `vm` module `runInNewContext` allows prototype-chain traversal to access the host global scope if injected context objects inherit from the host's standard `Object.prototype`. This allowed attackers to execute `process.env.constructor.constructor('return process')().env` and leak master environment variables (like API keys) from the host machine.
**Learning:** Initializing the `vm` sandbox context with `{ process: ... }` object literals is insecure, because the literal shares the prototype chain with the node execution context.
**Prevention:** Always initialize `vm` sandbox contexts and ALL injected nested properties (like `process` or `env`) using `Object.create(null)` to completely sever the prototype chain link to the host environment. Additionally, always explicitly lock down dynamic evaluation within the VM using `vm.createContext` with `codeGeneration: { strings: false, wasm: false }`.
