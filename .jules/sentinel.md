
## 2025-02-14 - Prevent Backend Secret Exposure in Vite Config
**Vulnerability:** The Vite configuration (`frontend/vite.config.ts`) was explicitly mapping the backend environment variable `env.GEMINI_API_KEY` to `process.env.API_KEY` and `process.env.GEMINI_API_KEY` via the `define` block. This bypassed `.env` protections by instructing Vite to statically replace references to those strings during compilation, inadvertently bundling backend secrets into the `.js` output served to clients.
**Learning:** Using Vite's `define` feature dynamically with variables retrieved from `.env` loaded via `loadEnv` can be incredibly dangerous if one inadvertently maps sensitive variables to variables expected by third-party frontend dependencies or internal code testing. Dependencies might crash if variables they expect aren't present at all, but the actual key itself doesn't need to be there.
**Prevention:** If frontend dependencies require `process.env` properties, define them as empty strings (`JSON.stringify("")`) instead of removing them entirely to prevent ReferenceErrors, while safely omitting the actual backend secrets. Always rely exclusively on `import.meta.env.VITE_*` prefixes for intended public keys.
