## 2025-02-27 - Node.js VM Sandbox Escape via Prototype Pollution
**Vulnerability:** A sandbox escape was possible in `backend/src/utils/codeRunner.js` because the `vm.runInNewContext` function was used with an ordinary JavaScript object for its context (which inherits `Object.prototype`).
**Learning:** Initializing the VM sandbox using standard object notation (e.g., `process: {}`) creates objects that retain their prototype chain. This allows the sandbox to traverse up to the host context's prototypes, enabling sandbox escapes via constructors (e.g., `process.env.constructor.constructor('return process')()`).
**Prevention:** Always use `vm.createContext` combined with `vm.runInContext`. Additionally, strictly ensure that ALL injected context objects, including nested properties like `process` and `process.env`, are created entirely devoid of a prototype chain using `Object.create(null)`. Finally, explicitly disable strings and wasm execution by passing `{ codeGeneration: { strings: false, wasm: false } }` to the context creation.
