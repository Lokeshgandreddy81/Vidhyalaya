## 2023-10-07 - Secure VM module execution against Sandbox Escape
**Vulnerability:** The codebase was running user-provided code via the Node `vm` module using `runInNewContext(code, { process: { exit: () => {} } })`. This allowed malicious code to escape the sandbox via prototype chain traversal, by grabbing `process.exit.constructor` to obtain the `Function` constructor from the host, and subsequently extracting host objects like `process.mainModule.require` or accessing environment variables.
**Learning:** Initializing a `vm` context with a standard JS object literal, or injecting host-created functions (even no-ops), leaves standard Object/Function prototypes exposed. Malicious code inside the VM can climb these prototypes to break the isolation.
**Prevention:** Always use `vm.createContext` initialized strictly with an object devoid of prototype inheritance: `Object.create(null)`. Additionally, recursively instantiate any nested objects via `Object.create(null)` and completely avoid passing host-created functions into the context. Set `codeGeneration: { strings: false, wasm: false }` to block dynamic code execution escapes.
