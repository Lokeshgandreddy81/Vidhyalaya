## 2026-08-01 - Node.js VM Sandbox Escape Mitigation
**Vulnerability:** The codebase allowed arbitrary code execution using Node.js `vm.runInNewContext`. An attacker could exploit this by using prototype property chains (e.g., `process.env.constructor.constructor('return process')()`) to bypass the VM boundaries and gain access to the host's `process` object.
**Learning:** Initializing the VM context sandbox object with standard JavaScript literal objects or without explicit null prototypes leaves the sandbox vulnerable to prototype pollution. Furthermore, the VM context allowed for implicit `eval` capabilities through constructors.
**Prevention:** Always initialize injected VM context objects (including nested attributes) using `Object.create(null)` to strip prototype properties. Additionally, explicitly block string-based code generation (like WebAssembly and eval equivalents) using `vm.createContext({ codeGeneration: { strings: false, wasm: false } })` before execution.
