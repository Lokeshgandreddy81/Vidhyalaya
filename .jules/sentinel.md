## 2026-06-21 - [CRITICAL] Prevented Server-Side Request Forgery via BYOK Header Configuration
**Vulnerability:** The `aiClientRouter.js` component trusted the client-supplied `x-byok-endpoint` custom endpoint URL, passing it directly into the server-side fetch calls (e.g., inside `callOpenAICompatibleStream`). This allowed attackers to craft headers that could exploit the backend to make network requests on their behalf targeting internal IP ranges.
**Learning:** BYOK architectures must explicitly sandbox connection boundaries. Because users can supply any URL, it is critically important to perform IP and DNS whitelisting or explicitly block private ranges, loopback addresses (localhost/127.x.x.x/0.0.0.0), and cloud metadata service IPs (`169.254.x.x`), as well as enforce TLS via `https:`.
**Prevention:** Wrote the custom helper `validateCustomEndpoint` to parse the provided URI and block requests attempting to reach private/internal IPs using strict Regex and parsing checks against the requested hostname. This is executed before any BYOK requests are processed.
