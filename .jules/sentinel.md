## 2024-05-20 - VM Sandbox Escape via Prototype Chain
**Vulnerability:** Node.js `vm` module sandbox escape using prototype chain (`process.env.constructor.constructor('return process')()`). The sandbox was initialized with an inline object `{ process: { ... }, global: {}, require: null }`. Because these objects inherit from `Object.prototype`, their `.constructor` points back to the host context's `Object` constructor. The `process.exit` function injected from the host context also retains `Function.prototype`. This allows malicious scripts to climb the prototype chain and execute arbitrary code in the main application context, leaking sensitive information like `process.env`.
**Learning:** Initializing a VM context with standard objects is inherently unsafe in Node.js because the context objects retain references to their constructors in the parent context. Host functions must never be passed directly into a VM context.
**Prevention:** Always use `Object.create(null)` recursively to build the sandbox context. Do not pass host functions (like `process.exit = () => {}`) into the VM environment. Furthermore, explicitly initialize contexts with `vm.createContext` and configure `codeGeneration: { strings: false, wasm: false }` to disable `eval()` and `new Function()`.
