## 2025-02-14 - Fix Sandbox Escape Vulnerability in Node.js VM
**Vulnerability:** A sandbox escape vulnerability existed in `backend/src/utils/codeRunner.js` because `vm.runInNewContext` was provided with an execution context consisting of standard Objects and host-created functions (`() => {}`). An attacker could execute arbitrary code outside the sandbox by exploiting the prototype chain (e.g., `this.process.env.constructor.constructor('return process')()`) since standard Objects inherit properties like `constructor` which eventually points to the host's `Function`.
**Learning:** Initializing an execution context object using standard notation `{}` makes it inherit from `Object.prototype`, which retains reference to global constructors. A true sandbox context must strictly sever all prototype links. Furthermore, `runInNewContext` inherently lacks fine-grained control over Code Generation compared to `createContext` where options like `strings: false` can be specified.
**Prevention:** Always build the execution context explicitly using `Object.create(null)` recursively for all nested structures (e.g. process, env). Always initialize VMs with `vm.createContext` utilizing the option `{ codeGeneration: { strings: false, wasm: false } }` to mitigate prototype chain traversal and dynamic code execution via `Function` or `eval`. Avoid passing host-created closures into the VM, as they retain host `Function.prototype`.
