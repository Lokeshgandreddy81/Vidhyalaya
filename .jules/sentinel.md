## 2024-11-07 - Node.js VM Sandbox Escape via Prototype Traversal
**Vulnerability:** The `executeSanitizedUserCode` function in `backend/src/utils/codeRunner.js` initialized its sandbox environment using standard object literals and injected a host function (`process.exit`), allowing malicious scripts to escape the VM context via prototype traversal (e.g., `this.constructor.constructor('return process')().env` or `process.exit.constructor...`).
**Learning:** Initializing the VM sandbox context with `Object.create(null)` is not sufficient if nested objects (like `process` or `process.env`) are created as standard objects or if host functions are injected, as their prototype chains retain access to the global host environment. Furthermore, `vm.createContext` with `codeGeneration: { strings: false, wasm: false }` is required to prevent string-to-code execution bypasses.
**Prevention:** Always use `Object.create(null)` recursively for ALL objects passed into a VM context. Completely avoid injecting host-created functions, and strictly use `vm.createContext` with restrictive options (disabling string code generation) executed via `vm.runInContext`.
