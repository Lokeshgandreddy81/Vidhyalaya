## 2024-05-18 - Fix Node.js VM Sandbox Escape Vulnerability
**Vulnerability:** The application used Node.js `vm.runInNewContext` to execute untrusted user code, passing standard JavaScript object literals for the execution context (e.g. `{ process: ... }`). This structure is highly vulnerable to prototype chain escapes.
**Learning:** Even when injecting a sanitized context object into the `vm` sandbox, if the objects are instantiated via standard object literals, they inherit from the host environment's `Object.prototype`. An attacker executing code inside the VM can climb this prototype chain using properties like `.constructor` to gain access to the host's `Function` constructor and subsequently break out to the main process, allowing arbitrary code execution (e.g. `this.process.env.constructor.constructor('return process')()`).
**Prevention:** Always initialize Node.js `vm` contexts and all deeply nested injected objects using `Object.create(null)` to completely sever the prototype chain to the host environment. Furthermore, explicitly disable runtime code generation by creating the context with `createContext(sandbox, { codeGeneration: { strings: false, wasm: false } })` before running it via `runInContext`.
