## 2025-03-05 - Fix XSS Vulnerability in CodeSandbox Regex Highlighting
**Vulnerability:** CodeSandbox `highlightCode` constructed custom syntax-highlighted HTML using regex replacements. Although the implementation correctly HTML-encoded basic input (`<`, `>`, `&`), directly passing complex regular-expression-generated HTML strings to `dangerouslySetInnerHTML` risks cross-site scripting (XSS) bypasses from malicious syntax or changes in highlighting rules.
**Learning:** Manual regex-based HTML construction and escaping for `dangerouslySetInnerHTML` is fragile. Security enhancements like `DOMPurify` should be implemented to establish defense-in-depth even if a custom encoder exists. The memory also highlighted that applying `DOMPurify.sanitize()` securely allows code snippet tags without stripping valid tokens or styling classes necessary for the highlighter.
**Prevention:** Consistently apply `DOMPurify.sanitize()` around dynamic inputs destined for `dangerouslySetInnerHTML`, particularly those originating from user-provided code strings combined with manual regex manipulations. Additionally, when contributing Sentinel fixes, ensure proper comments explaining the vulnerability are included in the source code according to the security agent's operating guidelines.

## 2025-03-05 - Vitest jsdom ES Module Compatibility with Node 18
**Vulnerability:** Not a direct security vulnerability, but a critical infrastructure issue affecting verification pipelines. Upgrading `jsdom` to v29 introduces a hard requirement for modern ES module environments and breaks compatibility with Node 18 inside `vitest` tests, manifesting as `ERR_REQUIRE_ESM` when resolving transitive dependencies like `@exodus/bytes/encoding-lite.js` from `html-encoding-sniffer`.
**Learning:** `jsdom` version 29 sets stricter module requirement bounds. If the CI runner or infrastructure utilizes Node 18, utilizing bleeding-edge `jsdom` versions causes the test suite to catastrophically fail to spin up worker forks, failing the PR build suite.
**Prevention:** Pin `jsdom` to version `^25` in projects demanding Node 18 backwards compatibility to ensure stable test environment initialization.
