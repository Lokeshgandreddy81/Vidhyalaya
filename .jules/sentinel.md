## 2025-07-04 - SSRF in AI Client Router
**Vulnerability:** The backend allowed users to supply custom endpoints for AI providers (e.g., via the `x-byok-endpoint` header) without validating the destination. This allowed Server-Side Request Forgery (SSRF) where attackers could point the backend to internal network resources, loopback addresses, or non-HTTPS services.
**Learning:** The `aiClientRouter.js` accepted any custom URL string and passed it directly to `fetch()` without analyzing if the IP resolves to an internal target. Standard string matching on the URL is not sufficient due to DNS rebinding and obfuscation; true validation requires DNS resolution (using `{ all: true }` in Node) prior to connecting.
**Prevention:** Always validate custom user-supplied endpoint URLs by enforcing the `https:` protocol and performing DNS resolution to ensure no returned IP address maps to an internal or reserved network space before attempting a request. Do not substitute the hostname with the IP in the final request to preserve TLS SNI checks.
