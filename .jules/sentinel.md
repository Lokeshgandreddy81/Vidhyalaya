## 2025-07-16 - [CRITICAL] VM Sandbox Escape in executeSanitizedUserCode
**Vulnerability:** The `executeSanitizedUserCode` function used the native `vm.runInNewContext` to execute potentially untrusted user code. It initialized the context mask object using standard object literal syntax `{}`. Because `{}` inherits from `Object.prototype`, an attacker executing code inside the VM could access `this.constructor.constructor("return process")()` to escape the context, bypass sandboxing entirely, and gain access to the host's `process` object. This could have led to Remote Code Execution (RCE) on the main Node.js process and access to environment secrets.
**Learning:** Initializing sandbox environments in `vm.runInNewContext` with plain objects is fundamentally unsafe because they carry prototype chain properties that allow attackers to dynamically reach out to the host environment context constructors. Injecting host functions (like a mocked `exit` function) compounds this risk as they provide further entrypoints.
**Prevention:** Always use `Object.create(null)` to instantiate a completely clean object with a null prototype chain when defining a sandbox context. Additionally, avoid passing host objects or host-defined functions directly into the sandbox unless absolutely necessary and heavily scrutinized, as they might provide bypass conduits.
