## 2024-05-18 - Prevent Server-Side Request Forgery (SSRF) on Custom AI Endpoints
**Vulnerability:** The application accepts a custom AI endpoint URL via the `x-byok-endpoint` HTTP header and uses it directly to initiate outbound HTTP requests from the backend server without any validation. This creates a critical Server-Side Request Forgery (SSRF) vulnerability. An attacker can supply an internal IP address (e.g., `127.0.0.1`, `10.x.x.x`, or IPv6 equivalents) or a malicious domain resolving to an internal IP (DNS Rebinding) to probe internal network services, read sensitive metadata APIs, or exploit internal services.
**Learning:** Using untrusted user input directly as a URL for outbound HTTP requests in Node.js (via `fetch` or other HTTP clients) is highly dangerous. Standard validation checks like regex matching against loopback addresses can be bypassed using IPv4-mapped IPv6 addresses (like `::ffff:127.0.0.1`), hexadecimal formats, or DNS rebinding.
**Prevention:** Always parse and validate untrusted URLs. Enforce expected protocols (like `https:`). Reject raw internal IPs and perform DNS resolution (using `dns.lookup`) to check if the target domain resolves to any internal IPs. Handle IPv4-mapped IPv6 loopbacks properly. While a custom network agent is best for mitigating TOCTOU (Time of Check to Time of Use) attacks, pre-request DNS validation provides a solid defense-in-depth layer against most automated SSRF exploitation attempts.
