## 2024-03-01 - Prevent SSRF in AI client router
**Vulnerability:** The application allowed users to specify a custom API endpoint (`x-byok-endpoint`) for their BYOK (Bring Your Own Key) AI providers. This endpoint was passed directly to a backend `fetch` call without validation, exposing the server to Server-Side Request Forgery (SSRF). An attacker could hit internal metadata services (e.g., `http://169.254.169.254/latest/meta-data/`) or internal APIs.
**Learning:** Even though this endpoint is intended for external AI providers (OpenAI, Anthropic), blindly trusting header values to construct server-to-server HTTP requests is dangerous.
**Prevention:** Always validate and sanitize user-provided URLs. Use the built-in `URL` object to parse the URL. Enforce strict protocol checks (e.g., requiring `https:`) and actively block resolution to loopback (`localhost`, `127.x.x.x`), private IP ranges (`10.x.x.x`, `192.168.x.x`, `172.16-31.x.x`), and link-local ranges (`169.254.x.x`). Enforcing HTTPS provides an incredibly robust defense because internal targets almost never have valid TLS certificates matching attacker-controlled domains, mitigating advanced techniques like DNS rebinding.
