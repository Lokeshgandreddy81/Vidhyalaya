## 2025-10-24 - AI Custom Endpoint SSRF Prevention
**Vulnerability:** The `backend/src/utils/aiClientRouter.js` directly accepted and executed HTTP requests against a user-provided `customEndpoint` header without any validation. This created a severe Server-Side Request Forgery (SSRF) vulnerability, allowing attackers to force the server to make requests to internal services, cloud metadata endpoints (e.g., AWS IMDS `169.254.169.254`), or loopback addresses.
**Learning:** Never pass raw user-provided URLs directly into server-side `fetch` calls. The `URL` constructor's `hostname` property must be thoroughly validated against both string-based blacklists and actual DNS resolution to catch DNS rebinding and internal IP masking. Additionally, brackets around IPv6 addresses (e.g. `[::1]`) returned by `parsedUrl.hostname` can bypass strict string equality checks.
**Prevention:** Always implement a dedicated `validateEndpoint` layer before execution. This layer must enforce HTTPS, block known loopback strings (accounting for IPv6 brackets), parse standard IPv4 strings, and importantly, perform `dns.lookup` on custom domains to verify they do not resolve back to internal/private IP address ranges (e.g., `10.x.x.x`, `192.168.x.x`, `127.x.x.x`).
