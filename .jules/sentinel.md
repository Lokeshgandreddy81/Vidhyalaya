## 2024-05-24 - [Fix VM Sandbox Escape Vulnerability in codeRunner.js]
**Vulnerability:** The code runner utility used Node.js `vm.runInNewContext` to isolate Javascript user execution. However, injecting host-created objects and functions (e.g. `process.exit = () => {}`) without stripping prototypes allows a malicious script to escape the sandbox. By accessing `this.process.exit.constructor('return process')()`, an attacker can access the main Node.js process and leak environment secrets (e.g., `process.env`).
**Learning:** `vm` contexts share prototype chains by default with their injected context objects unless specifically stripped using `Object.create(null)`. `vm.runInNewContext` offers limited protection and cannot adequately safeguard against prototype escalation when standard JS objects are introduced. Host-created functions (like arrow functions) inherently carry the `Function.prototype`, enabling escape.
**Prevention:** Always construct `vm` execution contexts explicitly with `vm.createContext`. Use strictly `Object.create(null)` recursively for any variables, objects, or context bindings supplied to the sandbox to sever the prototype chain, and NEVER inject host-created functions. In addition, always enforce `{ codeGeneration: { strings: false, wasm: false } }` to block dynamic execution mechanisms.
