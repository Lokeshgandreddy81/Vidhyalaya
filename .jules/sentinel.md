## 2025-02-14 - Missing Security Middleware in Express (NoSQL Injection & HPP)
**Vulnerability:** The backend Express application lacked standard security middleware to protect against NoSQL Injection and HTTP Parameter Pollution. While `express-mongo-sanitize` and `hpp` were installed as dependencies in `package.json`, they were not actually mounted in the Express `app.use()` pipeline. This left the application potentially vulnerable to crafted malicious queries or array-based parameter pollution bypasses.
**Learning:** Having security packages listed in `package.json` does not mean they are active. Sentinel must explicitly verify their usage in the application pipeline (e.g., `index.js` or `app.js`).
**Prevention:** Always mount security middleware (`helmet`, `express-mongo-sanitize`, `hpp`) at the top of the Express request pipeline immediately after the body parsers to ensure all incoming data is sanitized before reaching the route handlers.
## 2025-02-14 - CI Failures Due to Incompatible Node Version (Node 18 vs Frontend Dependencies)
**Vulnerability:** Not a security vulnerability, but a deterministic CI pipeline failure. The `.github/workflows/ci.yml` matrix was configured to run tests on Node `18.x`. However, modern frontend dependencies used in the project (such as `jsdom`, `@google/genai`, and `@tailwindcss/oxide`) explicitly require Node `>= 20`. This mismatch caused `EBADENGINE` and ESM resolution errors (`ERR_REQUIRE_ESM`) in the CI environment.
**Learning:** CI pipelines must be aligned with the strictest Node version requirements of all project dependencies. Running outdated Node versions will cause opaque failures that block development pipelines.
**Prevention:** Ensure the GitHub Actions `node-version` matrix strictly conforms to the `engines.node` requirements of all installed packages, prioritizing the most restrictive requirement (e.g., `>= 20`).
