## 2024-08-02 - Fix VM Sandbox Escape via Prototype Chain in executeSanitizedUserCode
**Vulnerability:** The `executeSanitizedUserCode` function in `backend/src/utils/codeRunner.js` executed user code using Node.js's `vm.runInNewContext`. Because the context object was created as a standard JavaScript object (which inherits from `Object.prototype`), untrusted code could traverse the prototype chain (e.g., using `this.constructor.constructor('return process')()`) to escape the sandbox and gain access to the host's global context, including sensitive environment variables.
**Learning:** Initializing the VM sandbox context with standard object literals (like `{ process: ... }`) is unsafe because the prototype chain provides a pathway out of the sandbox.
**Prevention:** Always construct the sandbox environment and its nested objects using `Object.create(null)` to ensure they have no prototype. Additionally, use `vm.createContext` explicitly and configure the `codeGeneration` option to disable `strings` (eval/Function) and `wasm` for defense-in-depth, executing the code with `vm.runInContext`.
