## 2025-02-14 - Fix SSRF via BYOK Custom AI Endpoint
**Vulnerability:** The AI client router allowed users to provide a custom endpoint URL via the `x-byok-endpoint` header, which was directly fetched without validation. This allowed SSRF (Server-Side Request Forgery) attacks where a malicious user could target internal network resources or AWS metadata endpoints.
**Learning:** Even when delegating requests to third-party APIs (like OpenAI or Anthropic), allowing user-defined proxy endpoints requires strict validation, specifically enforcing HTTPS, checking the hostname, and proactively performing DNS lookups to block domains that resolve to internal IPs (preventing DNS rebinding or simple obfuscation).
**Prevention:** Always validate user-supplied URLs used in server-side fetches. Enforce expected protocols (HTTPS), reject known private/loopback IP ranges (including IPv4-mapped IPv6), and resolve hostnames via `dns.lookup({ all: true })` before issuing requests to ensure the final destination is safe.
