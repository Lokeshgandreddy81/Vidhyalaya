## 2024-05-24 - [VM Sandbox Escape]
**Vulnerability:** A VM sandbox escape vulnerability existed in `backend/src/utils/codeRunner.js` where `executeSanitizedUserCode` used `runInNewContext` and passed a host-created function (`process.exit = () => {}`) into the sandbox context. An attacker could use this host function to access its constructor (`Function`), escaping the sandbox by dynamically executing `constructor('return process')()` to gain access to the host's global `process` object.
**Learning:** `runInNewContext` with a custom context is not perfectly isolated if host-created objects (especially functions or classes, which inherit from the host's `Function.prototype` or `Object.prototype`) are injected. Malicious scripts can walk the prototype chain or use constructors to break out.
**Prevention:** To secure VM sandbox execution, initialize the sandbox environment using `Object.create(null)` to remove prototype chains. Use `vm.createContext` with `{ codeGeneration: { strings: false, wasm: false } }` to prevent dynamic code execution via `eval` or `new Function`. Also, never inject host-created functions or full host objects directly into the sandbox context. Use primitives or safely constructed objects based on `null`.
