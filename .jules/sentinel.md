## 2025-02-14 - VM Sandbox Escape Vulnerability
**Vulnerability:** In `codeRunner.js`, `runInNewContext` is used to execute untrusted JavaScript code with a simplistic sandbox object: `{ process: { ... }, global: {}, require: null }`. However, because the standard host objects (like the function assigned to `process.exit`) are injected directly into the sandbox without `Object.create(null)`, their prototype chain remains intact. This allows attackers to traverse the chain to the host's `Function` constructor (`this.process.exit.constructor('return process')()`), enabling a complete escape from the sandbox and unauthorized access to host resources, including `process.env`.
**Learning:** `vm.runInNewContext` with a plain JavaScript object is insecure for untrusted code execution in Node.js. Injecting any standard host function or object exposes the host's prototype chain.
**Prevention:** To secure the VM: use `vm.createContext` with `codeGeneration: { strings: false, wasm: false }`, execute via `vm.runInContext`, ensure ALL nested objects are created recursively via `Object.create(null)` to eliminate prototype traversal, and avoid injecting host-created functions (like arrow functions) into the context.
