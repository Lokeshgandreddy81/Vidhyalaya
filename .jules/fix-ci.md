## 2026-06-22 - Fix CI Pipeline ESM Require Error in frontend tests
**Vulnerability/Bug:** During automated GitHub Action execution, `vitest run` triggered an unhandled `ERR_REQUIRE_ESM` error: `require() of ES Module /.../@exodus/bytes/encoding-lite.js from /.../html-encoding-sniffer/lib/html-encoding-sniffer.js not supported`. This was caused by the usage of `jsdom@29.1.1` deep within Vitest's `jsdom` testing environment, which transitively depends on an ESM package (`@exodus/bytes`) that was being incorrectly processed as CommonJS by `html-encoding-sniffer`.
**Learning:** Certain `jsdom` v25+ transitions fully adopted `whatwg-url` and other WHATWG specifications that depend on modern ESM-only libraries. In environments explicitly restricted or incorrectly flagged as CommonJS during test bootstrapping, this creates strict fatal module import barriers.
**Prevention:** Pinning or explicitly controlling `jsdom` resolutions inside the frontend application's `devDependencies` can mitigate nested transitive ESM compatibility regressions from unexpected node-module trees during CI executions. Using `jsdom@25.0.1` locally in tests avoids these deep `html-encoding-sniffer` dynamic-import crashes entirely.
