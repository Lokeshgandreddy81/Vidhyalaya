# Security Audit (SECURITY_AUDIT.md)

This report details a security audit of Vidyal.ai's codebase, evaluating authentication, authorization, environment variables, token lifetimes, input validations, and secrets management.

---

### 1. Authentication Bypass Vulnerability (Critical Risk)

#### The Bypass Endpoint
*   **File Path**: [backend/src/routes/auth.js:L9-L25](file:///Users/lokeshgandreddy/Sara/Vidhyalaya/backend/src/routes/auth.js#L9-L25)
*   **Code Block**:
    ```javascript
    router.post('/token', (req, res) => {
      const { userId } = req.body;
      if (!userId) {
        return res.status(400).json({ error: 'userId is required' });
      }

      const user = { id: userId };
      const secret = process.env.JWT_SECRET;
      ...
      const token = jwt.sign(user, secret, { expiresIn: '24h' });
      res.json({ token });
    });
    ```
*   **Vulnerability**: This endpoint acts as an authentication bypass. Anyone can send a POST request with an arbitrary `userId` and receive a valid JWT session token, allowing full access to that user's profile and data.
*   **Remediation**: Delete this endpoint immediately before deploying to production. For development testing, restrict this route using environment checks:
    ```javascript
    if (process.env.NODE_ENV !== 'development') {
      return res.status(403).json({ error: 'Access denied' });
    }
    ```

#### Gemini API Key Exposure
*   **File Path**: [frontend/.env.local](file:///Users/lokeshgandreddy/Sara/Vidhyalaya/frontend/.env.local)
*   **Content**:
    ```
    VITE_GEMINI_API_KEY=AIzaSyBii0sL6zmjL5DNWP4ekbHhWu8jrc75ago
    ```
*   **Vulnerability**: Commit files containing active Google Gemini API credentials exposes them to potential misuse if the repository is pushed to a public version control host.
*   **Remediation**:
    1. Revoke the exposed API key in the Google Cloud Console.
    2. Add `.env.local` to the [.gitignore](file:///Users/lokeshgandreddy/Sara/Vidhyalaya/frontend/.gitignore) file to prevent local environment overrides from being committed.
    3. Provide instructions in the configuration guide for developers to generate their own Gemini API keys.

### 3. Long Session Token Lifetimes (Medium Risk)

#### Session Lifespan
*   **File Path**: [backend/src/routes/auth.js:L88-L93](file:///Users/lokeshgandreddy/Sara/Vidhyalaya/backend/src/routes/auth.js#L88-L93)
*   **Assessment**: User session tokens generated via Google SSO are configured with a 30-day expiration:
    ```javascript
    const sessionToken = jwt.sign(
      { id: profile.userId, email: profile.email },
      jwtSecret,
      { expiresIn: '30d' }
    );
    ```
*   **Vulnerability**: A 30-day lifespan is long for a session token. Without a rotation or revocation mechanism, a compromised token remains valid for up to a month.
*   **Remediation**: Use short-lived access tokens (e.g., 15 minutes) paired with secure, HTTP-only refresh cookies to rotate sessions safely.

### 4. Input Sanitization & XSS Risk (Low-Medium Risk)

#### Markdown Render Injection
*   **Assessment**: The application renders content generated by AI models and user notes using the [ContentRenderer.tsx](file:///Users/lokeshgandreddy/Sara/Vidhyalaya/frontend/src/components/ui/ContentRenderer.tsx) component.
*   **Risk**: If an AI model output or a shared study note contains malicious `<script>` tags or javascript protocol links, they could be executed in the user's browser, leading to XSS vulnerabilities.
*   **Remediation**: Sanitize all HTML outputs inside the markdown parser using a library like `dompurify` before rendering them.
