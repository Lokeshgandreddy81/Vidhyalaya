# Classroom Experience Masterplan

## Purpose

This document defines how notes, editor, browser, terminal, AI mentor, and progress should work together for maximum learning.

Do not optimize for maximum information. Optimize for maximum learning.

## Classroom Principle

Every surface must answer one question:

```text
How does this help the student learn the current objective faster?
```

If it does not answer that, it should be hidden, simplified, or deferred.

## Current Surfaces

- Content renderer.
- Notes editor.
- Smartboard.
- Whiteboard.
- Neural map.
- SARA chat.
- Quiz panel.
- Vault.
- Terminal panel.
- Code sandbox.
- Browser preview.

The opportunity is not adding more. The opportunity is orchestration.

## Ideal Classroom Layout

### Mission Header

Always visible:

- Current mission.
- Current goal.
- Why it matters.
- Current state: learning, practicing, debugging, reflecting.

### Main Work Surface

Shows the environment needed now:

- Content when introducing.
- Editor when building.
- Browser when observing output.
- Terminal when practicing workflows.
- Scenario state when debugging.

### Mentor Rail

SARA stays available but not noisy:

- Observes context.
- Gives short interventions.
- Stores reflections.
- Surfaces memory when relevant.

### Learning Memory Strip

Quiet indicators:

- Concept at risk.
- Skill being practiced.
- Mistake pattern detected.
- Suggested review.

No XP, levels, badges, or decorative progress bars.

## Surface Roles

### Notes

Role:

- Capture durable understanding.
- Store reflections.
- Convert mistakes into principles.

Notes should not become a dumping ground for AI summaries.

### Editor

Role:

- Let the student change real code.
- Support SARA ghost highlights.
- Connect edits to browser and tests.

### Browser

Role:

- Show consequence.
- Teach cause and effect.
- Highlight UI elements related to code.

### Terminal

Role:

- Teach workflows, Git, environment, tests, and debugging.
- Simulate safe mistakes.
- Validate missions.

### AI Mentor

Role:

- Orchestrate the loop.
- Diagnose stuckness.
- Adapt help.
- Challenge assumptions.
- Generate reflections.

### Progress

Role:

- Show mastery evidence.
- Show what remains weak.
- Show what is ready for review.

Progress is not a trophy system.

## Session Flow

1. Start with a mission.
2. Briefly establish why it matters.
3. Ask for prediction or plan.
4. Student acts in the work surface.
5. Cortex observes.
6. SARA intervenes only when useful.
7. Verify outcome.
8. Reflect.
9. Update memory, skill graph, and journal.
10. Recommend next mission.

## Cognitive Load Rules

- One primary objective at a time.
- One active work surface at a time unless comparison is needed.
- Hide unrelated panels during deep work.
- Prefer visual pointing over long text when the issue is spatial.
- Prefer short next action over multi-step lectures.

## Classroom Success Standard

A great Cortex session feels like:

```text
I knew what I was trying to do.
I made real attempts.
SARA helped exactly when I needed it.
I understood my mistake.
I can do the next version with less help.
```
