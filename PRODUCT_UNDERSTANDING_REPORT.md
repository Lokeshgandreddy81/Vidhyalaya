# Product Understanding Report

## Executive Summary

Cortex is an adaptive learning operating system whose core product is not the editor, terminal, browser, notes, or chat. The core product is learning acceleration through a personal AI mentor that remembers the student, adapts the path, creates meaningful practice, and turns mistakes into durable skill.

The current product already has the ingredients of a differentiated learning environment: generated paths, a classroom session, notes, SARA chat, concept maps, terminal scenarios, and study tools. The risk is that the experience can still feel like several powerful tools placed side by side instead of one coherent mentor-led journey.

The product standard should be:

> A student should leave Cortex able to say: "I became a developer."

That requires Cortex to measure evidence of mastery, not just completion; to guide the next best action, not just display options; and to remember struggle, recovery, and confidence across sessions.

## Product Vision

Cortex should become the highest-retention AI mentor for technical mastery. It should not compete by having more lessons. It should compete by making each hour inside the product more valuable than an hour anywhere else.

The winning product is a living mentor system:

- It knows what the student is trying to become.
- It remembers what the student has tried.
- It tracks mistakes, confidence, retention, and transfer ability.
- It converts every session into a better next session.
- It creates realistic missions instead of passive tutorials.

## Product Mission

Help students learn faster, remember longer, build confidence, and develop real developer judgment through adaptive AI mentorship.

This mission rejects vanity completion. A completed path is not enough. Cortex should care whether the student can use the skill in a new context, recover from failure, explain the concept, and make the next decision with confidence.

## Current Product Surfaces

### Dashboard and Classroom Entry

Current role: entry point for learning paths and active modules.

What works:

- Clear route into generated learning paths.
- Active path spotlight.
- Quick resume affordance.

Main gap:

- The dashboard must become a learning command center, not a course library. It should surface next best action, current weakness, review needs, and recent evidence.

### Learning Path System

Current role: generated curriculum structure with phases and modules.

What works:

- Gives learners a structured plan from an open-ended goal.
- Supports module progress and path continuity.

Main gap:

- Paths still risk feeling like courses. The next evolution is missions, scenarios, and mastery evidence attached to each module.

### Session Window

Current role: immersive learning environment with content, notes, SARA, maps, terminal, and supporting tools.

What works:

- Strong raw surface area for learning.
- Several modes support different cognitive needs: explanation, visualization, notes, code, terminal, and checks.

Main gap:

- The session needs stronger orchestration. Cortex should make the next action obvious: read, explain back, practice, debug, reflect, or move forward.

### Terminal Experience

Current role: virtual shell and mission/scenario execution environment.

What works:

- Terminal missions and scenarios are a strong differentiator.
- Mistake-aware SARA bridge improves debugging support.
- Local virtual filesystem lowers risk and lets students practice safely.

Main gap:

- Terminal results should feed long-term learning memory: command fluency, repeated mistakes, recovery time, and confidence after repair.

### Notes Experience

Current role: learner workspace for capture and review.

What works:

- Keeps learning artifacts close to the session.
- SARA vault and saved evidence begin to create memory.

Main gap:

- Notes should become structured reflection and retrieval material. Cortex should distinguish copied information from learner-generated understanding.

### Browser and Preview Experience

Current role: supports visual feedback for generated or practiced work.

What works:

- Important for coding education because students need to see behavior, not only code.

Main gap:

- Browser state should be part of ghost mentor actions: highlight broken UI, point to rendered effects, and connect code changes to visible outcomes.

### AI Experience

Current role: SARA chat, tutor, prompt-based explanations, quiz generation, terminal support.

What works:

- SARA already has enough integration points to become a mentor instead of a chatbot.
- Terminal mistake context is a strong foundation for personalized repair.

Main gap:

- SARA needs persistent learner memory and structured actions. The mentor should say less generic text and do more contextual teaching, pointing, adapting, and evaluating.

### Progress Experience

Current role: path percentage, completed modules, study time, quiz outcomes.

What works:

- Basic continuity exists.

Main gap:

- Completion is not mastery. Progress must evolve into skill evidence: confidence, retention, transfer, practice count, error patterns, and velocity.

## Current User Journey

### Entry

The student enters through a dashboard or generated path. The product is strongest when it asks for a meaningful learning goal and turns it into structure.

Risk:

- A student may not know what to do next once inside a dense session.

Product response:

- Always surface one recommended next action, backed by learning memory.

### Study

The student reads, asks SARA, opens concept maps, takes notes, and may practice in code or terminal.

Risk:

- Tool switching can create cognitive load.

Product response:

- The AI mentor should orchestrate modes: "Read this", "Now predict", "Now run a check", "Now fix the scenario", "Now reflect."

### Practice

The student uses quizzes, terminal missions, concept checks, and relationship puzzles.

Risk:

- Practice can be mistaken for proof of mastery.

Product response:

- Label practice outcomes as evidence signals, then require transfer checks before declaring durable mastery.

### Reflection

The product has early vault/journal ingredients, but the reflection loop is not yet the central ritual.

Risk:

- Students finish sessions without seeing what changed in their mind.

Product response:

- Every session should end with: learned, still weak, mistake pattern, confidence, and next mission.

## Business Goals

Cortex should win by owning learning outcomes, not content volume.

Important business goals:

- Increase student trust through accurate guidance and visible learning memory.
- Improve retention by making progress feel real, not performative.
- Create a defensible moat through personalized learner memory and mission generation.
- Convert free or sandbox users by showing meaningful mentorship in the first session.
- Make long-term use compelling by letting students see their skill identity change over time.

## Product Principles

1. Learning evidence over activity metrics.
2. Mentor guidance over tool discovery.
3. Missions over chapters.
4. Recovery over perfection.
5. Reflection over passive completion.
6. Memory over one-off chat.
7. Transfer over recall alone.

## Strategic Diagnosis

Cortex is closest to a breakthrough when it behaves like a mentor who has a memory, a plan, and standards. It is weakest when it behaves like a powerful dashboard of disconnected learning widgets.

The next major product leap should be to make every surface answer the same question:

> What should this student do next to become more capable?
